PD Packet Field Guide

把 USB PD 封包拆成看得懂的邏輯地圖

這份頁面把 PD analyzer 裡的 SOP、Msg、Obj、Rev、Data 欄位串起來， 用固定流程判斷 Header、PDO、RDO、VDM 與常見 Data Object。

1先看 SOP，知道這包講給誰
2再看 16-bit Header，知道有幾個 Data Object
3每 4 bytes 拆一個 32-bit object

PD 封包骨架

一般 PD message 的固定骨架如下。CRC 與 EOP 在實際線上存在，但 analyzer 通常會隱藏。

SOPStart of Packet，決定對象
16-bit HeaderMsg Type、Obj 數量、ID、Role、Rev
0~7 x 32-bit Data ObjectPDO、RDO、VDM、Alert、BIST...
32-bit CRC檢查封包正確性
EOPEnd of Packet

SOP 是收件人

同一包只會有一種 SOP 類型，不會同時有 SOP 和 SOP'。

SOP 類型對象白話理解
SOPPort Partner一般 Source / Sink 之間的 PD 溝通，例如 Source_Cap、Request、Accept、PS_RDY。
SOP'近端 Cable Plug / E-Marker問線材這一端的能力，例如 Discover Identity 判斷是否 5A E-Marked cable。
SOP''遠端 Cable Plug / E-Marker問線材另一端 plug，較常見於 active cable、USB4/TBT、debug 或 compliance 測試。
Hard ResetPort Partner重置 PD 合約與狀態機。
Cable ResetCable Plug重置 cable communication。

16-bit Message Header

Header 是第一個必拆欄位，決定這包是 Control Message 還是 Data Message。

Bit欄位含意判斷重點
15Extended0 = normal message；1 = extended message。Extended = 1 時，後面還有 Extended Message Header。
14:12Number of Data Objects0~7 個 32-bit Data Object。000 看 Control Message；大於 0 看 Data Message。
11:9Message ID0~7 循環序號。GoodCRC 對應上一包的 ID。
8Power Role0 = Sink；1 = Source。Analyzer 常用它配合方向顯示 SRC/SNK。
7:6Spec Revision00 = PD1.0；01 = PD2.0；10 = PD3.0。看到 V3 通常是 raw 10。
5Data Role0 = UFP；1 = DFP。DR_SWAP 就是在切換這個角色。
4:0Message Type5-bit message code。同一 code 在 Control / Data 欄可能代表不同東西。

重點：不要只看 Message Type raw code。一定要先看 NDO。NDO = 0 看 Control Message；NDO > 0 看 Data Message。

32-bit Data Object 分類

Data Object 是 4 bytes 容器，真正含意要靠 Header 的 Message Type 決定。

PDO

Source / Sink Capabilities

宣告可供應或可接受的能力。包含 Fixed、Battery、Variable、PPS APDO。

RDO

Request

Sink 用來向 Source 要某一個 PDO，例如 5V/3A 或 PPS 指定電壓電流。

VDM / VDO

Vendor Defined

Discover Identity、Discover SVIDs、Discover Modes、Enter Mode 等都在這類。

Message TypeData Object 類型Excel 對應 Sheet
Source_CapabilitiesPDO listFixed / Battery / Variable / PPS APDO
Sink_CapabilitiesSink PDO listSink Fixed PDO 或其他 PDO sheet
RequestRDORequest RDO / PPS Request RDO
Vendor_DefinedVDM Header + VDO32-bit VDM / Generic Object
Alert / BIST / Battery_Status專用 32-bit objectAlert / BIST / Battery Status sheet

32-bit Battery PDO

Battery PDO 用「功率 W」描述能力，不直接用電流 A。它可出現在 Source_Capabilities 或 Sink_Capabilities。

31:30Supply Type = 01
29:20Maximum Voltage，Raw x 50mV
19:10Minimum Voltage，Raw x 50mV
9:0Maximum Power，Raw x 250mW
Bit欄位Raw / 單位詳細說明
31:30Supply Type01代表 Battery Supply PDO。若不是 01，表示這個 32-bit object 不是 Battery PDO，可能應放到 Fixed、Variable 或 APDO。
29:20Maximum Voltage10-bit，50mV/step可提供或可接受的最高電壓。計算式：Maximum Voltage = Raw x 0.05V。例如 raw 240 = 12.00V。
19:10Minimum Voltage10-bit，50mV/step可提供或可接受的最低電壓。計算式：Minimum Voltage = Raw x 0.05V。例如 raw 100 = 5.00V。
9:0Maximum Power10-bit，250mW/step此 PDO 的最大功率。計算式：Maximum Power = Raw x 0.25W。Battery PDO 的核心是 W，不是 A。

好記：Battery PDO = 電壓範圍 + 最大功率。例如 5V~12V / 15W。若要估電流，用 I = P / V。

32-bit Variable PDO

Variable PDO 也描述電壓範圍，但它的能力單位是「最大電流 A」，不是功率 W。

31:30Supply Type = 10
29:20Maximum Voltage，Raw x 50mV
19:10Minimum Voltage，Raw x 50mV
9:0Maximum Current，Raw x 10mA
Bit欄位Raw / 單位詳細說明
31:30Supply Type10代表 Variable Supply PDO。若不是 10，表示這個 object 類型不對。
29:20Maximum Voltage10-bit，50mV/step可變範圍的最高電壓。計算式：Raw x 0.05V。
19:10Minimum Voltage10-bit，50mV/step可變範圍的最低電壓。計算式：Raw x 0.05V。
9:0Maximum Current10-bit，10mA/step此電壓範圍內可提供或可接受的最大電流。計算式：Raw x 0.01A。

Battery vs Variable：Battery PDO 看 W；Variable PDO 看 A。兩者都有最小/最大電壓，但最後一段欄位單位不同。

32-bit Request RDO

RDO 是 Sink 對 Source 說：「我要你 Source_Capabilities 裡第幾個 PDO，以及我要多少電流/功率」。

Fixed / Variable RDO

要求固定或可變 PDO

低 20 bits 通常是 Operating Current 與 Maximum Current，單位 10mA。

PPS RDO

要求 PPS APDO

會帶 Output Voltage 與 Operating Current，PPS voltage 單位常用 20mV。

32-bit VDM / VDO

Vendor Defined Message 的第一個 32-bit object 通常是 VDM Header，後面才是各種 VDO 或 vendor payload。

BitVDM Header 欄位Raw / 值詳細說明
31:16SVID16-bitStandard or Vendor ID。0xFF00 常見為 USB-IF SVID；其他值可能是 DisplayPort、Thunderbolt、廠商自訂等。
15VDM Type0 / 10 = Unstructured VDM，後面 vendor 自訂；1 = Structured VDM，欄位依 PD 規格解析。
14:13Structured VDM Version00/01/...Structured VDM 版本。常見 00 = v1.0，01 = v2.0；其他依 PD revision 確認。
12:11Reserved通常 00保留欄位。若非 0，先確認 Structured VDM 版本與 endian。
10:8Object Position0~7用於 Enter Mode、Exit Mode、Attention 等命令，指定 mode/object position。Discover 類命令常為 0。
7:6Command Type00/01/10/1100 = Initiator；01 = ACK；10 = NAK；11 = BUSY。
5Reserved通常 0保留欄位，通常不應為 1。
4:0Command5-bit00001 Discover Identity；00010 Discover SVIDs；00011 Discover Modes；00100 Enter Mode；00101 Exit Mode；00110 Attention。
VDO 類型常見在哪裡用途
ID Header VDODiscover Identity ACK描述對方是 USB host/device、cable plug、AMA、VPD 等身分與 capability。
Cert Stat VDODiscover Identity ACK認證或憑證相關資訊。
Product VDODiscover Identity ACKVendor ID、Product ID、bcdDevice 等產品資訊。
Cable VDO問 SOP' / SOP'' cable identity描述 cable 電流能力、速度、passive/active、latency、termination 等線材能力。
SVID VDODiscover SVIDs ACK一個 VDO 通常可放兩個 SVID，用來列出支援的功能家族。
Mode VDODiscover Modes ACK描述某個 SVID 底下可進入的 mode，例如 DP Alt Mode 或 vendor mode。

好記：VDM Header 先看 SVID、Command Type、Command。如果 Command 是 Discover Identity/SVIDs/Modes，後面的 VDO 才是回答內容。

建議解析流程

拿到 analyzer 一列資料時，就照這個順序拆。

  1. 先看 SOP 是 SOP、SOP' 還是 SOP''，決定這包是給裝置還是 cable plug。
  2. Data 欄前 2 bytes 放到 16-bit Header，看 NDO / Obj 與 Message Type。
  3. Obj = 0 通常是 Control Message，後面沒有 32-bit Data Object。
  4. Obj > 0 時，Header 後面每 4 bytes 拆成一個 32-bit Data Object。
  5. 若 Message Type 是 Source_Capabilities 或 Sink_Capabilities，再看每個 PDO 的 bit 31:30 判斷 Fixed / Battery / Variable / APDO。
  6. CRC 與 EOP 實際線上存在，但 analyzer 通常隱藏；GoodCRC 是 message，不是尾端 CRC 欄位。

本頁是學習與除錯用速查整理。版本相依或 vendor-defined 欄位仍需搭配實際 PD revision、線材能力與 analyzer raw capture 判斷。
