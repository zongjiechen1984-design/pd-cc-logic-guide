USB PD 封包樹狀解析：Header 完整展開版

以 USB PD R3.2 V1.2, Table 6.2 Message Header 與 Table 6.3 Number of Data Objects 為基準，從封包外層一路拆到 Header 每個 bit。

回主教材
請先輸入第一行 Header，系統會判斷是否需要第二行。
SOP*Start of Packet，決定收件人
16-bit Header每個 message 一定從這裡開始
0~7 Data ObjectData Message 或 Extended Message 才依條件出現
CRC32-bit，PHY/Protocol 檢查
EOPEnd of Packet
手繪式樹狀展開：SOP* -> Header -> Control/Data/Extended -> CRC -> EOP
這一區照你的白板圖閱讀：左邊是封包起點，往右一路分支。所有分支最後都會收斂到 CRC 與 EOP；差別在於 SOP* 決定收件對象，Header 決定後面有沒有 Data Object，以及 Message Type 要查哪一張表。
  • PD Packet實體線上完整順序：SOP* -> 16-bit Message Header -> optional Data Portion -> CRC -> EOP
    • SOP一般 Port-to-Port：Source / Sink 之間的主要 PD message。
      • 16-bit HeaderSOP 情境：bit8=Power Role，bit5=Data Role。
        • bit15 Extended決定這包是不是 Extended Message。
          0 Control/Data Message：再看 NDO。NDO=0 是 Control；NDO>0 是 Data。
          1 Extended Message：Header 後面接 Extended Message Header + payload。
        • bit14:12 NDONumber of Data Objects，決定 Header 後面有幾個 32-bit Data Object。
          000 0 objects：Control Message，Header 後直接 CRC -> EOP。
          001 1 object：Header 後 4 bytes data。
          010 2 objects：Header 後 8 bytes data。
          011 3 objects：Header 後 12 bytes data。
          100 4 objects：Header 後 16 bytes data。
          101 5 objects：Header 後 20 bytes data。
          110 6 objects：Header 後 24 bytes data。
          111 7 objects：一般 Data Message 最大數量。
        • bit11:9 MessageID0~7 rolling counter，用於 retry 與 GoodCRC 對應。
          000 MessageID 0。
          001 MessageID 1。
          010 MessageID 2。
          011 MessageID 3。
          100 MessageID 4。
          101 MessageID 5。
          110 MessageID 6。
          111 MessageID 7，下一個新 ID 回到 0。
        • bit8 Power RoleSOP 封包才用 Source/Sink 解讀。
          0 Sink：送出這包 SOP message 的 power role 是 Sink。
          1 Source：送出這包 SOP message 的 power role 是 Source。
        • bit7:6 Spec Revision宣告這包 message 使用的 USB PD specification revision。
          00 Rev1.0 deprecated；R3.2 receiver 應視為 Rev2.0。
          01 Rev2.0。
          10 Rev3.x。
          11 Reserved。
        • bit5 Data RoleSOP 封包才用 DFP/UFP 解讀。
          0 UFP：送出這包 SOP message 的 data role 是 UFP。
          1 DFP：送出這包 SOP message 的 data role 是 DFP。
        • bit4:0 Message Type先看 bit15 與 NDO，才知道要查 Control / Data / Extended 哪一張表。
          • ControlExtended=0 且 NDO=000：SOP -> Header -> Control Type -> CRC -> EOP。
          • DataExtended=0 且 NDO>000：SOP -> Header -> Data Type -> Data Object -> CRC -> EOP。
            • ExtendedExtended=1：SOP -> Header -> Extended Header -> Payload -> CRC -> EOP。
      • SOP'Cable Plug Communication：常用於 cable identity / SVID / modes 等。
        • 16-bit HeaderSOP' 情境：bit8=Cable Plug，bit5=Reserved。
          • bit15 Extended決定 SOP' 這包是不是 Extended Message。
            0 Control/Data Message。
            1 Extended Message，後面接 Extended Message Header + payload。
          • bit14:12 NDOSOP' 也用 NDO 決定後面 data object 數量。
            000 0 objects：Control Message。
            001 1 object：常見 VDM Header-only request。
            010 2 objects：VDM Header + 1 VDO。
            011 3 objects。
            100 4 objects。
            101 5 objects。
            110 6 objects。
            111 7 objects。
          • bit11:9 MessageIDSOP' 有自己的 MessageID counter，不和 SOP 共用。
            000 SOP' MessageID 0。
            001 SOP' MessageID 1。
            010 SOP' MessageID 2。
            011 SOP' MessageID 3。
            100 SOP' MessageID 4。
            101 SOP' MessageID 5。
            110 SOP' MessageID 6。
            111 SOP' MessageID 7。
          • bit8 Cable PlugSOP' / SOP'' 時 bit8 不代表 Source/Sink。
            0 Port，也就是 DFP/UFP 端送出的 cable message。
            1 Cable Plug or VPD 送出的 cable message。
          • bit7:6 Spec RevisionSOP' 使用的 PD revision。Cable Plug 也要依 revision 解讀。
            00 Rev1.0 deprecated；receiver 視為 Rev2.0。
            01 Rev2.0。
            10 Rev3.x。
            11 Reserved。
          • bit5 ReservedSOP' / SOP'' 時 receiver ignores this field。
            0 Reserved：不要解讀為 UFP。
            1 Reserved：不要解讀為 DFP。
          • bit4:0 Message Type一樣先看 bit15 與 NDO，再查 Control / Data / Extended table。
            • ControlSOP' -> Header -> Control Type -> CRC -> EOP。
            • DataSOP' -> Header -> Data Type -> 32-bit Data Object；常見 Vendor_Defined / VDM -> CRC -> EOP。
              • ExtendedSOP' -> Header -> Extended Header + Payload -> CRC -> EOP。
        • SOP''另一個 Cable Plug 視角；仍是 cable plug communication，不是一般 Port-to-Port。
          • 16-bit HeaderSOP'' 情境：bit8=Cable Plug，bit5=Reserved。
            • bit15 Extended決定 SOP'' 這包是不是 Extended Message。
              0 Control/Data Message。
              1 Extended Message，後面接 Extended Message Header + payload。
            • bit14:12 NDOSOP'' 也用 NDO 決定後面 data object 數量。
              000 0 objects：Control Message。
              001 1 object。
              010 2 objects。
              011 3 objects。
              100 4 objects。
              101 5 objects。
              110 6 objects。
              111 7 objects。
            • bit11:9 MessageIDSOP'' 有自己的 MessageID counter，不和 SOP/SOP' 共用。
              000 SOP'' MessageID 0。
              001 SOP'' MessageID 1。
              010 SOP'' MessageID 2。
              011 SOP'' MessageID 3。
              100 SOP'' MessageID 4。
              101 SOP'' MessageID 5。
              110 SOP'' MessageID 6。
              111 SOP'' MessageID 7。
            • bit8 Cable PlugSOP'' / SOP' 時 bit8 不代表 Source/Sink。
              0 Port，也就是 DFP/UFP 端送出的 cable message。
              1 Cable Plug or VPD 送出的 cable message。
            • bit7:6 Spec RevisionSOP'' 使用的 PD revision。
              00 Rev1.0 deprecated；receiver 視為 Rev2.0。
              01 Rev2.0。
              10 Rev3.x。
              11 Reserved。
            • bit5 ReservedSOP'' / SOP' 時 receiver ignores this field。
              0 Reserved：不要解讀為 UFP。
              1 Reserved：不要解讀為 DFP。
            • bit4:0 Message Type一樣先看 bit15 與 NDO，再查 Control / Data / Extended table。
              • ControlSOP'' -> Header -> Control Type -> CRC -> EOP。
              • DataSOP'' -> Header -> Data Type -> 32-bit Data Object；常見 cable / Vendor_Defined response -> CRC -> EOP。
                • ExtendedSOP'' -> Header -> Extended Header + Payload -> CRC -> EOP。
